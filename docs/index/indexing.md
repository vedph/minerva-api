# Indexing Data

This page contains the procedure for creating the Minerva index from the pseudonymized TEI documents generated by `an_tool`.

## Prerequisites

- you have XML and metadata files ready, named according to the description below (this naming results from downloading files from their BLOB store).
- you have a running PostgreSQL service.
- you have Pythia binary files in some folder. The procedure below assumes that you open a terminal window located in that folder.

>⚠️ In most cases, you will need to prepare the received TEI documents with some systematic [filtering](filtering.md) to remove slight imperfections from the original sources.

## Procedure

>This procedure refers to a Windows environment. Just change the folder names to adapt it to other environments. Also, you can freely change any folder name; the folders used here are just suggested for commodity.

▶️ (1) create a desktop `ac` **folder** and copy into it:

- [atti-chiari.json](atti-chiari.json).
- the documents you want to index and their metadata files.

👉 The [profile](atti-chiari.json) assumes that the files are located and named according to this pattern:

- document file with extension `.xml`;
- document metadata file in the same directory, with the same name plus `.meta` added at its end. This is a CSV file.

So, for instance you will have:

- `civ-fi-app-cit342-000000_01.xml`
- `civ-fi-app-cit342-000000_01.xml.meta`

etc. This is the naming scheme resulting when you download files from their BLOB repository.

▶️ (2) create the **database**:

```bash
./pythia create-db -c
```

▶️ (3) add the **profile**:

```bash
./pythia add-profiles c:/users/dfusi/desktop/ac/atti-chiari.json
```

▶️ (4) check that all **metadata files** are at place:

```bash
./pythia check-meta c:/users/dfusi/desktop/ac/*.xml
```

▶️ (5) **index** documents from your folder (you can add `-p` to preflight):

```bash
./pythia index atti-chiari c:/users/dfusi/desktop/ac/*.xml -o -x path -x gruppo-atto -x gruppo-nr
```

>The option `-x` is used to exclude document attributes from indexing. Here we exclude `path` which is an editorial detail about the BLOB store. When not indexing for the public application remove `-x gruppo-atto -x gruppo-nr` as groups make sense when documents themselves are not split.

💡 To **inspect** the filtered text during indexing, you can add options `-r DUMP_DIR -u 1` or `-u 2`, where `1` means dumping and `2` dumping without indexing. This way you can see the plain text projected from the TEI document and superposable to it, which is used in all these processing types requiring no markup (like in NLP), e.g.:

```bash
./pythia index atti-chiari c:/users/dfusi/desktop/ac/*.xml -o -x path -x gruppo-atto -x gruppo-nr -r c:/users/dfusi/desktop/ac/dump/ -u 1
```

▶️ (6) adjust the **profile** for production, by replacing the text retriever ID and text renderer script in the database profile:

```bash
./pythia add-profiles c:/users/dfusi/desktop/ac/atti-chiari-prod.json -i atti-chiari
```

>Note the `-i atti-chiari` option, which assigns the ID `atti-chiari` to the profile loaded from file `atti-chiari-prod.json`. This has the effect of overwriting the profile with the new one, rather than automatically assigning an ID based on the source file name (which would result in adding a new profile with ID `atti-chiar-prod`).

This replaces profile `atti-chiari` with the one from file `atti-chiari-prod.json`, which was derived from `atti-chiari.json` by applying the following changes:

- you use the _SQL-based retriever_ which will get the document's content from the database rather than from the file system:

```json
"TextRetriever": {
  "Id":"text-retriever.sql.pg"
}
```

instead of `"TextRetriever":{"Id":"text-retriever.file"}`.

- you _embed the XSLT script_ in the text renderer options rather than loading it from a file. To this end, copy the XSLT code, minify it (just to make it more compact), and paste it into the `Script` option replacing the XSLT file path, e.g.:

```json
"TextRenderer": {
  "Id": "text-renderer.xslt",
  "Options": {
    "Script": "...PASTE_HERE_YOUR_XSLT_CODE...",
    "ScriptRootElement": "{http://www.tei-c.org/ns/1.0}body"
  }
}
```

>Note that before pasting into JSON you must first escape any `"` as `\"` to avoid JSON syntax errors!

These changes make the database contents independent from their hosting environment, because no more references to the file system are required.

If you want to quickly check structures like sentences, you can dump them like:

```bash
./pythia dump-spans -o c:/users/dfusi/desktop/spans-snt.csv -t snt -i 1
./pythia dump-spans -o c:/users/dfusi/desktop/spans-tok.csv -t tok -i 1
```

>💡 At this time it can be a good idea to **backup** the database, so you can just rebuild the word index when required:

```bash
pg_dump --username=postgres -f c:/users/dfusi/desktop/pythia-nowords.sql pythia
```

Should you want to _restore_ this database and start over from n.7, remove the `pythia` database, re-create it as a new empty database, and then restore:

```bash
psql -U postgres -d pythia -f c:/users/dfusi/desktop/pythia-nowords.sql
```

▶️ (7) build the **word index**:

```bash
./pythia index-w -c ^date_value=3 -c ^nascita-avv=7 -x author -x data -x date-value -x path -x gruppo-atto -x gruppo-nr -x sede-raccolta -n abbr -n address -n email -n foreign -n org-f -n org-m -n pn-f -n pn-m -n pn-s -p ABBR -p DATE -p EMAIL -p NUM -p PROPN -p SYM -p X
```

>Option `-x` excludes the specified document attribute. Option `-n` excludes the words having any of the specified attributes (to remove proper names). Option `-c` defines the count of classes for document attribute bins. The `^` prefix before `date_value` means that we want integer only bins for that attribute, as it represents just a year value. Option `-p` excludes the specified POS from the index.

▶️ (8) optionally, **dump** the database into binary files:

```bash
./pythia bulk-write c:/users/dfusi/desktop/ac/bulk
```

You can also backup the resulting database:

```bash
pg_dump --username=postgres -f c:/users/dfusi/desktop/pythia.sql pythia
```

Should you need to, you can dump spans from the database like (here `-t`=span type and `-i`=document ID):

```bash
./pythia dump-spans -o c:/users/dfusi/desktop/spans.csv -t snt -i 1
```
