# Filtering

The documents generated by `an-tool` often present glitches coming from human markup errors, author's errors, or corner cases which might impact the indexing process.

Thus, before the [indexing](./indexing.md) procedure you typically have to run a set of filters to fix at least the majority of the known issues. Pythia can filter texts immediately before indexing, but here we prefer to apply filters and get a new set of document files, so that we can check them before further processing and use them as our verified source.

To this end, we use the Proteus CLI tool for filtering according to a [JSON profile](./filters.json). While this tool allows for much more complex transformations, here we just stick to text replacements.

So, without further details, we can just focus on the replacements themselves, which are defined in the `Replacements` property. For each replacement, there is:

- the `Source` text or regular expresion to find.
- the `Target` text to replace.
- `IsPattern` is true when source is a regular expression.
- (not applicable for XML scoped replacer) `Repetitions` is 1, unless you have to cycle for multiple replacements (for corner cases where the output of the replacement might be the input for the same replacement).

A Proteus-based filtering is structured into stages; each stage applies any number and type of filtering, and ends up into a new output file. Stages accumulate their changes, until the last output file, which is the end result. This allows users check each stage output.

## Filters

This describes each filter in [filters.json](filters.json), in their order.

### Stage dots1

XML scoped replacer by file:

- outside TEI `abbr`, `num`, `email`, `date`:
  - **replace dot** with U+2024 in "dot + digit(s)". This targets cases like "1.2" in numbering or "12.345" in a thousands separator or a date like "20.12.2024". This happens because often numbers or dates were not explicitly marked as such.
  - **replace dot** with U+2024 in "`>` + optional whitespaces + digit + dot". This target numbering which usually is immediately after some hilight or other markup. In general, a sequence like "1." could not be determined as a numbering rather than a mere number followed by a stop like in "ex art. 23."; but here we target a single digit preceded by a tag, with only whitespaces between them, which in most cases seems to be a pattern for numbering.

### Stage dots2

XML scoped replacer by file:

- **replace dot** with U+2024 in "U+2024 + digit(s) + dot". This ensures that a sequence in a numbering has no dot left (e.g. the last dot in "1.3.").
- **insert space** before the last character in "punctuation + non-(WS/digit)".
- **trim right** of `</TEI>`.
- **replace dot** with U+2024 in "currency symbol (`$£€`) + dot + whitespace(s) + digit".

## Stage misc

String replacer, by line:

- **trim left** of "WS + punctuation + WS".
- **replace U+00A0** with space (e.g. `il` + U+00A0 + `custode`).
- **replace ellipses** `(...)` and `[...]` with their counterparts with the Unicode ellipsis character instead of 3 dots.
- **remove whitespace(s)** in `“` + whitespaces or  whitespace(s) + `”`.
- **remove whitespace(s)** in whitespaces + `%` (e.g. `del 75 % a carico`).
- **remove spaces** in "`(` + spaces".
- **remove spaces** in "spaces + `)`".
- **replace ligatures** like `ﬃ` with their counterpart like `ffi` (e.g. `consolidata dell'Uﬃcio Edilizia`).
- **replace !** in "exclamation mark + `)`" (e.g. `(SIC!)`): replace `!` with `¡`.
- **replace ?** in "question mark + `)`" (e.g. `(davvero?)`): replace `?` with `¿`.
- **replace with accented** uppercase: "`AEIOU` + `’`".
- **replace smart quotes** `’` with `'`: smart quotes seem to be limited to cases of apostrophes only, so it is a required semantic adjustment for Unicode.

## Example

This example text sums up the above replacements:

(1) original:

```xml
<?xml version="1.0" encoding="utf-8"?>
<TEI xmlns="http://www.tei-c.org/ns/1.0">
  <teiHeader>
    <fileDesc>
      <titleStmt>
        <title>civ-ge-app-cit342-200911_01</title>
      </titleStmt>
      <publicationStmt>
        <p>Not published.</p>
      </publicationStmt>
      <sourceDesc>
        <p>Undisclosed.</p>
      </sourceDesc>
    </fileDesc>
  </teiHeader>
  <text>
    <body>
      <p rend="c"><choice><abbr>ecc.ma</abbr><expan xml:lang="ita">eccellentissima</expan></choice> CORTE DI APPELLO DI <placeName>GUARDIAGRELE</placeName>.</p>
      <p>Il signor Ammazzalamorte al 20.12.2024 deve 32.000 euro ai parenti della medesima . Motivi:</p>
      <p>1. uno;</p>
      <p>1.1. uno punto uno.</p>
      <p>Una virgola,senza spazio. O anche ,così.</p>
      <p>Una virgola fra spazi , perché no?</p>
      <p>Ancora: €.123 o $. 123 perché qualcuno confonde i simboli di valuta con le abbreviazioni!</p>.
      <p>Qui uso U+00A0 anziché spazio fra lettere: A B.</p>
      <p>Simboli vari: (...) e [...] e virgolette “ con spazi ” e 45 % con spazio e parentesi ( con spazi )!</p>

    </body>

```

## Dropped

The following filters were dropped because they might break other texts:

- letter + `(`: insert space between them:

```json
{
  "Source": "(\\p{L})\\(",
  "Target": "$1 (",
  "IsPattern": true,
  "Repetitions": 1
},
```

This can't be used to fix typos because there are texts like: "impone(va)", "è(ra)", "resta(va)no", etc.

## Checks

Things to check which cannot be fixed automatically in a robust way:

- spaced words, like "P E R" for "PER". To see whether there are any left, look for a regular expression like `\b[A-Z] [A-Z]`.

## Procedure

▶️ (1) place the [filters.json](filters.json) file in some folder.

▶️ (2) run the `proteus` tool with this command (adjust it according to your folder structure):

```bash
./proteus filter c:/users/dfusi/desktop/ac/_unfiltered/fi/*.xml c:/users/dfusi/desktop/ac/filters.json c:/users/dfusi/desktop/ac/fi/ -x xml
./proteus filter c:/users/dfusi/desktop/ac/_unfiltered/ge/*.xml c:/users/dfusi/desktop/ac/filters.json c:/users/dfusi/desktop/ac/ge/ -x xml
./proteus filter c:/users/dfusi/desktop/ac/_unfiltered/le/*.xml c:/users/dfusi/desktop/ac/filters.json c:/users/dfusi/desktop/ac/le/ -x xml
./proteus filter c:/users/dfusi/desktop/ac/_unfiltered/vt/*.xml c:/users/dfusi/desktop/ac/filters.json c:/users/dfusi/desktop/ac/vt/ -x xml
```

>There will be an output file for each stage, the final output having extension `.xml` (option `-x`). You can then use any diffing tool to compare the filtered results with the originals.

▶️ (3) rename the last step of each filtering result using some tool. In this case we just replace `_00003.xml$` with `.xml`. At this stage, you may want to diff the originals with the filtering results to check for issues.

When everything is OK, just replace the XML files to be indexed with the filtered files.
