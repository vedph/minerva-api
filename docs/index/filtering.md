# Filtering

The documents generated by `an-tool` often present glitches coming from human markup errors, author's errors, or corner cases which might impact the indexing process.

Thus, before the [indexing](./indexing.md) procedure you typically have to run a set of filters to fix at least the majority of the known issues. Pythia can filter texts immediately before indexing, but here we prefer to apply filters and get a new set of document files, so that we can check them before further processing and use them as our verified source.

To this end, we use the Proteus CLI tool for filtering according to a [JSON profile](./filters.json). While this tool allows for much more complex transformations, here we just stick to text replacements.

So, without further details, we can just focus on the replacements themselves, which are defined in the `Replacements` property. For each replacement, there is:

- the `Source` text or regular expresion to find.
- the `Target` text to replace.
- `IsPattern` is true when source is a regular expression.
- (not applicable for XML scoped replacer) `Repetitions` is 1, unless you have to cycle for multiple replacements (for corner cases where the output of the replacement might be the input for the same replacement).

A Proteus-based filtering is structured into stages; each stage applies any number and type of filtering, and ends up into a new output file. Stages accumulate their changes, until the last output file, which is the end result. This allows users check each stage output.

## Dots

Dots pose issues when they potentially interfere with sentence detection. Currently, these are the issues we are fixing here:

- **stage 1** ("by-file: dots1"): only outside `abbr` and `num` elements, replace the targeted dot with U+2024 in:
  - dot + digit(s). This targets cases like "1.2" in numbering or "12.345" in a thousands separator outside `num` (by human mistake).
  - replace `>` + optional whitespaces + digit + dot. This target numbering which usually is immediately after some hilight or other markup. In general, a sequence like "1." could not be determined as a numbering rather than a mere number followed by a stop like in "ex art. 23."; but here we target a single digit preceded by a tag, with only whitespaces between them, which in most cases seems to be a pattern for numbering.

- **stage 2** ("by-file: dots2"): this replaces the final dot in U+2024 + digit(s) + dot into U+2024, thus ensuring that a sequence in a numbering has no dot left (e.g. the last dot in "1.3.").

## Miscellaneous

- only outside `abbr`/`num`:
  - any of `.,;:?!` (when not preceded by `xml`, because we have `xml:lang` attributes) + no whitespace/digit/`<`: insert space (e.g. `articolo ,con`). Note that this does not cover stitched text like `resistente;2) in subordine` as numbers do use `,` and `.`.
  - whitespaces + any of `.,;:?!` + whitespaces: remove left whitespaces.

- replace code A0 with space (e.g. `il` + U+00A0 + `custode`).
- replace `(...)` and `[...]` with their counterparts with the Unicode ellipsis character instead of 3 dots.
- remove whitespace(s) in `“` + whitespaces or  whitespace(s) + `”`.
- whitespaces + `%`: remove whitespaces (e.g. `del 75 % a carico`).
- `(` + spaces: remove spaces.
- spaces + `)`: remove spaces.
- `ﬃ` and other ligatures replaced with their counterpart like `ffi` (e.g. `consolidata dell'Uﬃcio Edilizia`).
- exclamation mark + closing bracket (e.g. `(SIC!)`): replace `!` with `¡`.
- question mark + closing bracket (e.g. `(davvero?)`): replace `?` with `¿`.
- `AEIOU` + `’`: replace with the corresponding accented uppercase letter.
- `’` with `'`: smart quotes seem to be limited to cases of apostrophes only, so it is a required semantic adjustment for Unicode.

## Dropped

The following filters were dropped because they might break other texts:

- letter + `(`: insert space between them:

```json
{
  "Source": "(\\p{L})\\(",
  "Target": "$1 (",
  "IsPattern": true,
  "Repetitions": 1
},
```

This can't be used to fix typos because there are texts like: "impone(va)", "è(ra)", "resta(va)no", etc.

## Procedure

▶️ (1) place the [filters.json](filters.json) file in some folder.

▶️ (2) run the `proteus` tool with this command (adjust it according to your folder structure):

```bash
./proteus filter c:/users/dfusi/desktop/ac/*.xml c:/users/dfusi/desktop/ac/filters.json c:/users/dfusi/desktop/ac/filtered -x xml
```

>There will be an output file for each stage, the final output having extension `.xml`. You can then use any diffing tool to compare the filtered results with the originals.

▶️ (3) rename the last step of each filtering result using some tool. In this case we just replace `_00003.xml$` with `.xml`. At this stage, you may want to diff the originals with the filtering results to check for issues.

When everything is OK, just replace the XML files to be indexed with the filtered files.
